While working on this here website, I have mostly (at the time of writing anyway) been working with a version of violet that doesn't have a `serve` command, because I haven't made it yet. Instead, I've used `violet generate -l` to set `{{ site.prefix }}` to the full file path. This does _technically_ work, but it has issues.

For a static site, these fortunately don't matter all that much. I don't have CORS I need to worry about. However, for the [meta page](/meta), I `fetch()` a JSON file that contains stats generated by violet through the render. This does not work locally, because you can't fetch local files.

This is where a server would be useful, even a small one. As it turns out, Firefox actually provides one now as a feature of devtools.

In the devtool settings, there's a brand new section called local mode. You don't need to use the setting though, I get a popup saying that it could be opened in a (temporary) such domain.

![Screenshot showing a local mode mapping that maps website.localhost to a local filepath](/static/img/firefox-localhost-domains.png)

(Ignore the `.github.io` domain, I haven't got around to moving the git repo after discontinuing github as the main source)

Now I can just go to `website.localhost`, and it loads the rendered version of this page like it was loaded from a real server. This also means `/meta.html` works. Again, it functionally has a `fetch("/_violet-meta.json")` call, which breaks when it tries loading a file, but the local mode domains act like a proper server, so the browser can load resources like normal.

Don't worry, violet will still be getting serve functionality at some point :p This is still really nice though, and means web development in Firefox isn't anywhere near as dependent on there actually being a backing server. It's much more friendly to various forms of raw web requests.

The only downside is that it requires the devtools to be open, so it's likely not as useful for like games that are just exported HTML/CSS/JS files. I don't play any such games right now, but I am aware of a couple. They obviously work around the fetch limitation of browsers by not having the type of dependency I have, but I do wonder if local mode being made less dependent on devtools would make it easier to make such games. That's far outside my domain anyway. The only major use-case I have is localhost webdev on more classic websites.
